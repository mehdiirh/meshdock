# Decisions and questions for the owner

Proceeding without blocking questions, as requested.

- Linux targets: Debian/Ubuntu with systemd, root SSH, IPv4 transport addresses. Other operating systems are rejected before activation.
- Traffic contract: each compact mapping row chooses TCP, UDP, or both. Defaults and migrated legacy rows remain TCP. IPv6 tunnel addressing remains unsupported.
- Entry/exit are general-purpose roles (Iran/kharej are deployment examples, never hardcoded).
- One control-plane installation owns one topology. Many entry servers can connect to many exit servers. Shared entry ports in socket-based connections form pools; compact GRE ranges require exclusive intervals; pool policy is round-robin, least-connections, or ordered failover.
- Changes queue reconciliation immediately. Workers serialize deployment generations, coalesce obsolete queued revisions, retry transient failures, and retain rollback/recovery information.
- Secrets are encrypted with a separate persistent master key. Back up the database AND key; losing the key loses access to encrypted credentials.
- Password login is for administrators; programmatic clients use revocable, scoped Bearer API keys. Browser sessions use HttpOnly cookies plus CSRF protection.
- SSH host-key discovery requires explicit fingerprint confirmation before a server can deploy. This is necessary even when a password/key is already saved.
- Shared dependency packages remain installed after cleanup. Removing shared packages automatically can break unrelated applications.
- GRE is not encrypted. Backhaul TCP is token-authenticated, not encrypted. Rathole and reverse SSH provide encrypted transports; the UI must disclose capabilities accurately.
- No existing real servers are imported or changed by development or demos.

Questions for later: preferred public domain/TLS termination; multi-tenant workspaces and non-admin roles; IPv6; desired retention and alert integrations; hardware scale targets and provider firewall integration.

- Method tuning uses adapter-owned strict Pydantic models and a generic schema-driven UI. Per-link JSON overrides are migrated and included in immutable job snapshots; rollback uses previous generation files. Supported controls are deliberately allowlisted. Transport variants that require new TLS, binding or firewall behavior need adapter work; raw configuration passthrough is not supported. Numeric bounds are controller policy, not upstream capacity claims. See METHOD-SETTINGS.md.

- Removed the former 512/64 application caps after checking upstream configurations. All adapters accept full TCP ranges subject to listener allocation, management/control conflicts, actual descriptor limits and outgoing port space. Reverse SSH splits forwards across sessions of 4,096, leaving channel headroom. This is not a throughput or universal hardware-capacity guarantee; see PORT-MAPPINGS.md for sources and tested boundaries.
- GRE ranges use compact HAProxy listeners on both endpoints. Mixed single/range GRE connections use the compact path for every row and cannot share those public ports with another connection. Individual mappings retain HAProxy pools.
- Internal allocations belong to immutable deployment manifests, not a globally reserved public band. Existing compact JSON storage supports range intent without schema mutation; startup/migration preservation is tested.

- The owner confirmed there are no deployed installations. Use MeshDock names throughout: `MESHDOCK_*` settings, `meshdock-*` services, `/var/lib/meshdock`, `meshdock.sqlite3`, `meshdock_session`, and the `meshdock` Compose project. There are no legacy aliases or data migrations for the earlier development names. GRE interfaces use the short `md` prefix to remain within Linux's 15-byte interface-name limit.

- Transport expansion uses each pinned release's actual capabilities. Backhaul WSS clients require a verifying bridge because upstream skips certificate verification. Rathole ARM64 WS/WSS are rejected before activation because upstream ships an embedded build without WebSocket; do not advertise unsupported binary features or install an unverified substitute. Payload protocol support is validated separately from the outer transport.
- Deployment cancellation is cooperative and durable. Never kill an in-flight remote mutation; finish or time out, then compensate using host journals. Cancellation can require recovery after lost connectivity. Shared packages remain installed.
- Reconciliation skips unchanged server plans and restarts only units whose definitions or referenced files change. GRE/network ownership groups remain coordinated. Per-link affected IDs are persisted with new snapshots so unrelated edges do not inherit failure status. Capacity limits use stable buckets; oneshot network units keep their own small descriptor limit.
- Operational progress uses a small allowlisted JSON event protocol over the existing pinned SSH channel. Persist and stream those events, not arbitrary command stdout/stderr. Preserve safe failure categories, server identity and phase; never log tokens, private keys or raw generated configuration.

- Unfinished removals are derived from enabled applied links absent or disabled in desired state; no duplicate deployment-state table is introduced. The canvas uses a separate display projection, never silently merges retained links into saves. Retry and restore are revision-checked admin actions; both reconcile the current desired topology and the UI explicitly discloses other pending changes. Restore preserves original slot/secret material and refuses conflicting endpoint changes. An unresolved rollback is shown as uncertain.

- SSH access supports one explicitly configured jump host per target, with independent credentials and host-key pins. Store a copy of the jump settings on the target rather than an inventory reference, so later inventory edits cannot silently redirect authentication and rollback retains its original route. Target accounts remain root; jump accounts may be unprivileged. Do not forward agents, copy keys onto jump hosts, modify SSH forwarding policy, or silently fall back to direct access. Management-path changes alone do not restart unchanged tunnel plans.

- Force deletion commits cleanup per endpoint instead of restoring successful peer cleanup after an unreachable destination. Only related failed removals may be taken over from recovery. Unreachable peers require explicit skip acknowledgement, while failures remain retryable. Store versioned metadata and progress in existing job snapshots/receipts; retain conservative resource-slot and credential reservations for skipped cleanup. This is not a distributed transaction, and skipped endpoints are not automatically revisited.

- Board placement is shared presentation state, stored separately from operational snapshots. Only disconnected servers can move to inventory; desired, applied and pending-work dependencies keep endpoints visible. Disabled tunnel links count as connections. Jump arrows describe explicitly saved single-hop SSH routes and have separate non-connectable handles; unmatched or ambiguous host aliases appear as external read-only cards. Reciprocal routes are permitted as two independent direct-to-hop sessions, never recursive inventory chains.

- GRE TCP forwarding uses HAProxy for both individual ports and ranges. Compact range syntax does not avoid per-port sockets. Preserve offsets/exceptions, reject actual listener conflicts and check outgoing port/descriptor headroom. Keep host INPUT access rules, but generate no TCP NAT/FORWARD/MSS rules or forwarding sysctls. Legacy network journals remain readable for rollback and cleanup. Adapter plan versions migrate existing deployed endpoints on the next reconciliation; no remote changes occur merely from upgrading the controller. No database DDL changes are needed for version metadata in existing JSON snapshots.

- Compact GRE relays use a deterministic private port offset when the public span overlaps declared destination services, management or control listeners on the exit. This permits wildcard application listeners without changing their configuration. Exclusions retain their relative position; public and destination ports remain unchanged. If no alternate contiguous span fits, preserve the original relay ports and require actual preflight to approve them; full-range wildcard destinations cannot coexist with an overlapping HAProxy relay.

- UDP uses pinned adapters' native forwarding; GRE uses compact scoped UDP DNAT/SNAT rules. TCP remains HAProxy. Native socket links with UDP own a per-link `10.254.x.y/32` dummy address, protected against unsolicited external access, instead of weakening loopback filtering on public interfaces. Address units are dependencies of their consumers; generation rollback restores files, rules and owned sysctls. No shared Nginx or custom datagram daemon is installed.
- UDP mapping rows are exclusive per entry/protocol. TCP load balancing remains available where supported. TCP and UDP may use the same numeric port with different targets. Backhaul TCP's `accept_udp` is managed automatically and its extra internal listeners never become public mappings. UDP readiness does not claim arbitrary destination health; operators must test their actual application.
- Alembic revision `c81f6e902a14` makes desired legacy mappings explicitly TCP without rewriting immutable job/applied snapshots. Downgrade refuses to reinterpret UDP records; restore a matching database/key backup. Pinned upstream capability evidence and local real-packet tests are documented in PORT-MAPPINGS.md.

- GRE plan version 5 fixes UDP return-source selection for wildcard applications behind loopback DNAT using an owned NAT INPUT SNAT rule. The application sees a local peer; default routes and application configuration remain unchanged. Journal and invalidate only UDP conntrack tuples on the link's private GRE endpoints so an existing client's stale NAT does not defeat upgrades or rollback. Never flush global conntrack or clear unrelated public/TCP traffic. Old generation manifests without INPUT rules remain readable.

- Network health checks validate only chains declared by that endpoint plan. Optional NAT INPUT rules are absent on GRE entries and older saved generations; their absence must not crash deployment. Declared chains remain mandatory. Isolated packet tests run the production network/listener health checks on both endpoints after activation, with only systemd service checks omitted because the test namespaces run services directly.
