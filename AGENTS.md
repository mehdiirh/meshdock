# MeshDock development contract

- This is an open-source control plane. Never commit production IPs, hostnames, credentials, private keys, database files, logs, or user topology exports. Use RFC 5737 addresses in examples.
- Use `MESHDOCK_*` configuration, `meshdock-*` managed services, and `/var/lib/meshdock` remote state. GRE interfaces use the short `md` prefix to stay within Linux name limits. This unreleased project does not need aliases for earlier development names.
- Backend lives in backend/, frontend in frontend/. Keep adapters in backend/app/methods; extend the registry rather than adding method-specific branches to API handlers.
- `scripts/dev.sh` must force simulation unless `--prod` is explicitly passed, regardless of `.env` or inherited variables. Keep demo and real development databases and encryption keys separate; test both launch modes without contacting servers. Keep `sample.env` and `.env.example` identical and free of secrets.
- Docker startup goes through `python3 scripts/start.py`, which validates the effective Compose password before building or starting containers. Resolve configuration using Compose so shell overrides and env-file quoting match deployment; never print rendered configuration or credentials. Keep the API's first-start password check as a fallback for direct Compose usage.
- Default tests use simulated SSH and isolated state. Never connect to or change a real server unless the human explicitly authorizes that specific deployment.
- All mutating topology operations require authentication, optimistic revision checks, audit entries, and durable reconciliation jobs. Coordinates and other presentation changes must not deploy remote resources.
- Secrets are encrypted at rest and are never returned after creation. Logs, previews, errors, and exports must not reveal secrets. Pin SSH host keys; never auto-trust changes.
- Own only meshdock-* units, explicitly namespaced paths/interfaces/firewall chains. Never flush global firewall tables, rewrite default routes, or edit unrelated Xray/Nginx/SSH configuration.
- Preserve previous generations until health checks pass. Multi-host rollback is coordinated and can require recovery after connectivity loss; do not claim distributed atomicity or exactly-once execution.
- Cleanup removes owned resources, not unrelated software or packages shared with other applications.
- Every new API message and UI string needs English and Persian translations. Persian layout is RTL; network addresses and code remain LTR.
- Validate with pytest, frontend typecheck/build, UI tests, and Docker Compose config. Test failure, retry, rollback, concurrent revisions, auth, redaction, and cleanup.
- Use small commits prefixed [ADD], [UPDATE], or [BUGFIX]. Record assumptions and open product decisions in docs/DECISIONS.md. Be explicit about unverified environments.
- Database changes MUST use SQLAlchemy 2 models and a new Alembic revision in backend/alembic/versions. Never edit a released migration. Schema changes and the Alembic version update are atomic. Test upgrade from the previous schema with existing data, repeated startup, and failure rollback. No create-all/schema mutations in API handlers. Back up before production upgrades; downgrades restore a matching database/key backup.
- Maintain module boundaries: public validated contracts, application services, adapter registry, SSH transport, and remote agent. Version the API at /api/v1 and document extension contracts. Never use a UI-specific tunnel-method conditional in the API.
- Advanced settings belong to each adapter's strict `Options` model. Publish its schema through `/methods`; share conditional/cross-field rules with the generic UI. Reject unsupported/inactive settings, keep endpoint credentials and owned resources managed, and test persisted settings and previous-generation rollback. Preserve existing defaults and update the public browser schema fixture and en/fa labels when extending options. See docs/METHOD-SETTINGS.md.
- Translation storage: backend gettext catalogs in app/locales/{en,fa}/LC_MESSAGES/messages.po; frontend locale JSON files. No inline translation dictionaries or ternary language strings. Compile backend catalogs during builds and validate locale parity in tests.
- Backend dependencies and environments MUST use uv: maintain pyproject.toml and commit uv.lock, run uv sync --frozen. Frontend server state MUST use TanStack React Query. Frontend internationalization MUST use i18next/react-i18next with locale JSON files.

- Backend code MUST pass both Black formatting and Ruff lint checks using `backend/pyproject.toml`. Run the CI checks in `.github/workflows/ci.yml` before pushing; preserve imported pytest fixtures and opt-in safety markers when fixing lint errors. Use descriptive names, focused modules, explicit error boundaries, and shared helpers for repeated behavior; avoid compressed one-line control flow.

- Mapping intent is compact and transport-neutral: integer/range ports plus explicit entry-port exceptions. Preserve destination offsets. Capabilities and expansion limits belong to adapters, not API method-ID branches. No blanket public-port reservation bands. Bindings must declare address, protocol and port, and remote preflight must check actual listeners. GRE TCP forwarding uses HAProxy on both endpoints; UDP uses scoped, journaled kernel forwarding. Socket methods use native UDP listeners on owned private addresses. Keep range configs compact while counting every listening socket, checking conflicts/readiness/egress capacity, and ordering the router after GRE. Keep NAT journals compatible with previous generations and scope all new forwarding rules by protocol, interface and destination. Never expose private native listeners directly. Exercise the opt-in isolated Linux packet test when changing forwarding. Increment adapter plan versions when unchanged deployed topology needs recompilation.

- Do not present implementation batch sizes as upstream port limits. Source capability claims against pinned upstream versions. Large socket ranges require linear-time allocation, per-link listener addresses, bounded health probes, descriptor/outgoing-port preflight and compact UI previews. Reverse SSH batches must stay below channel ceilings and keep authorized-key restrictions scoped to the owned loopback address. Run the opt-in container-only socket tests when changing these paths; never alter host accounts for tests.

- Compare desired and applied server plans before reconciling. Keep unchanged hosts and units running; compare transitive referenced files so certificate changes restart their consumers. Test incremental apply AND rollback on shared entries, especially GRE network state.
- Cancellation must be durable and cooperative at remote-operation boundaries. Never terminate an SSH mutation to simulate cancellation. Retain rollback/recovery fencing, and test cancellation through commit and worker crash recovery.
- Emit only allowlisted, sanitized operational progress over SSH. Persist progress before streaming to clients; identify the failing server and phase. The collapsed deployment footer follows the latest revision, and failure coloring applies to affected links only.

- Keep applied-only connections and missing endpoints visible until deletion commits. Expose only allowlisted public snapshot fields. Restore must preserve slots and encrypted identities, validate current topology conflicts, and remain fenced during deployment/recovery. Test failed removal, partial apply, cancellation, retry, and restoration without touching live hosts.

- SSH jump settings are snapshot-owned endpoint configuration. Pin and authenticate both hops independently; keep secrets in the vault, protect referenced credentials, and preserve the saved route for cleanup/rollback. Never forward SSH agents, copy private keys onto jump hosts, change SSH daemon policy, or silently fall back to direct access. Test discovery, apply, rollback, credential retention and failure cleanup; run the opt-in loopback SSH/SFTP suite when changing transport behavior.

- Force deletion is a separate durable job: check every affected endpoint, preserve unrelated applied connections, and retain per-host progress across retries/restarts. Never let one missing host prevent peer cleanup. Only the explicitly selected unreachable server may be forgotten automatically after peer cleanup; skipping unreachable peers requires a second revision-checked admin action. Authentication/key errors and failed remote operations are not successful cleanup. Fence topology edits while unresolved, retain skipped-resource warnings/credentials/slots, and never use this workflow to bypass unrelated recovery.

- Board inventory placement is presentation-only and separately migrated. Never queue deployments or include visibility metadata in deployment snapshots. Reject hiding desired tunnel endpoints (including disabled links), SSH hop participants, and applied/in-flight cleanup dependencies. Show SSH management edges separately from traffic tunnels; keep external hops read-only, redact snapshot secrets, and never recursively follow an inventory server’s own saved jump path.

- UDP forwarding tests must include a real wildcard-bound responder and verify the returned source address/port; a crafted raw reply is not an application handshake test. For GRE loopback UDP, preserve the scoped INPUT SNAT and journaled private-endpoint conntrack invalidation. Test stale tuples with the same client source port, partial rule failure, rollback, and unrelated-flow preservation. Run the opt-in authenticated WireGuard test when changing this return path; TCP forwarding on the same mapping must also pass.
